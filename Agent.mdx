# Agent.mdx

## Documentation

Project docs live in `/docs` and use Mintlify.

All documentation pages must use `.mdx` so they are compatible with Mintlify. Use `.md` only for non-Mintlify files when explicitly required.

## Before Coding

Before making code changes, always read:

- `/docs/index.mdx`
- `/docs/brief.mdx`
- `/docs/BRD.mdx`
- `/docs/plans/master-plan.mdx`
- the related phase file in `/docs/plans`
- related docs in `/docs/features`
- related docs in `/docs/architecture`

Also read these when the task touches the area:

- `/docs/api` for backend routes or API behavior
- `/docs/database` for schema, Prisma, migrations, seed data, or SQL changes
- `/docs/deployment` for environment, build, hosting, or release changes
- latest files in `/docs/work-logs` when they exist

## After Coding

After finishing a task, update the related docs:

- update related `.mdx` files
- update `/docs/CHANGELOG.mdx`
- update `/docs/plans/master-plan.mdx` if phase status changes
- update the related phase file in `/docs/plans`
- create or update a work log in `/docs/work-logs`
- update `/docs/docs.json` if new pages are added

Do not consider a task complete if docs are outdated.

## Mintlify Validation

Before handing off documentation changes:

- make sure `npm run docs` starts Mintlify locally
- run `npm run docs:check` when validating docs
- report any validation command that cannot be run or fails

Mintlify local commands:

```bash
npm run docs
npm run docs:check
```

Current project script mapping:

```json
{
  "docs": "cd docs && mint dev",
  "docs:check": "cd docs && mint validate"
}
```

Note: this machine's installed Mintlify CLI supports `mint validate` for build validation. If a future CLI supports `mint build`, the docs check script can be changed deliberately after confirming the command exists.

## Scope Discipline

When the request is only about documentation setup, do not code product functionality.

When coding functionality, keep docs and implementation in sync in the same task.
