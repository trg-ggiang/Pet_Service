## Provider

The project uses PostgreSQL through Prisma. Supabase can provide the hosted PostgreSQL database.

Application settings are persisted in `app_settings`. Password reset OTP hashes and expiration metadata are stored in `password_reset_tokens`; raw OTP values are never stored. `users.auth_version` invalidates existing JWT sessions after a password reset.

## Schema

Main schema file:

```text
backend/prisma/schema.prisma
```

Key domains currently modeled include:

- Users and roles: `User`, `Customer`, `Staff`, `Doctor`
- Pets: species, breeds, pet profiles
- Appointments and doctor schedules
- Services, grooming, boarding, invoices, payments
- Notifications and reviews

Customer-created appointments store `requested_date` and `requested_time` on `appointments`.
These fields preserve the requested slot for both doctor-backed services and staff-backed services such as grooming or boarding.
Admin-managed doctor working windows are stored in `doctor_schedules`. Saving a window such as `08:00-16:00` creates 16 concrete 30-minute rows in `doctor_schedule_slots`.

Each doctor appointment links to one concrete slot through the unique `appointments.doctor_schedule_slot_id`. The slot owns booking state (`AVAILABLE`, `BOOKED`, `IN_PROGRESS`, `DONE`, or `OFF`), while the parent schedule remains the admin-owned working window.

Customer booking, staff rescheduling, and doctor follow-up booking may only reserve an `AVAILABLE` slot. Conditional slot reservation prevents two concurrent requests from booking the same slot.

## Environment

Required database-related variables:

```text
DATABASE_URL=
SUPABASE_URL=
SUPABASE_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

Do not commit real values.

## Commands

Generate Prisma client:

```powershell
npm --prefix backend run prisma:generate
```

## Rules

- Do not change `schema.prisma` without updating this page.
- Run Prisma generation after schema changes.
- Confirm migration and seed workflow with the team before applying data changes to shared environments.
