# Phase 8B-4 Real DB Appointment Concurrency

## 1. Muc tieu

Phase nay xac minh contract quan trong nhat cua appointment booking tren database that:

> Khi nhieu request cung dat mot doctor schedule slot dang `AVAILABLE`, chi mot request duoc chuyen slot sang `BOOKED`; tat ca request con lai phai thua ma khong ghi de ket qua.

Phase 8B-3 da xac minh contract nay bang stateful mock. Phase 8B-4 bo sung runner danh cho PostgreSQL/Supabase test project de phat hien cac van de ma mock khong the mo phong day du, nhu PostgREST conditional update, transaction isolation, network timing va row-level policy.

## 4. Database fixture bat buoc

Can mot slot danh rieng cho automated test voi cac dieu kien:

- Ton tai trong `doctor_schedule_slots`.
- `status = AVAILABLE` truoc khi chay.
- Khong co row nao trong `appointments` tham chieu `doctor_schedule_slot_id` cua slot.
- Doctor, schedule va ngay gio cua slot thuoc du lieu test, khong phai production.
- Khong co app/server/nguoi test khac cung su dung slot trong luc runner chay.

Runner se dung ngay tai preflight neu slot khong ton tai, khong `AVAILABLE`, hoac da lien ket appointment. Runner khong tu tao/xoa doctor, schedule hay appointment, vi lam vay se mo rong pham vi destructive mutation.

Co the kiem tra fixture bang SQL read-only:

```sql
select id, doctor_id, slot_date, start_time, end_time, status
from doctor_schedule_slots
where id = <TEST_DOCTOR_SLOT_ID>;

select id, status
from appointments
where doctor_schedule_slot_id = <TEST_DOCTOR_SLOT_ID>;
```

Ket qua truy van thu hai phai rong.

## 7. Flow cua moi lan chay

### Preflight

1. Xac minh explicit opt-in.
2. Chan remote URL neu thieu second opt-in.
3. Validate slot ID, rounds va contenders.
4. Doc slot fixture va yeu cau `AVAILABLE`.
5. Xac minh khong co appointment lien ket slot.

### Moi concurrency round

1. Dat fixture ve `AVAILABLE`.
2. Gui dong thoi `N` conditional updates:

```text
UPDATE doctor_schedule_slots
SET status = BOOKED
WHERE id = fixtureId AND status = AVAILABLE
```

3. Yeu cau dung mot response tra ve slot `BOOKED`.
4. Yeu cau `N - 1` response con lai tra `null`.
5. Doc lai database va xac minh slot dang `BOOKED`.

### Cleanup

Cleanup nam trong `finally`, nen van chay neu assertion, network call hoac mot round bi loi:

1. Dat slot ve `AVAILABLE`.
2. Doc lai va xac minh final status.
3. Xac minh runner khong tao appointment.

## 11. Pham vi khong bao gom

Runner nay co chu dich chi test atomic slot reservation. No khong tao appointment that va khong test UI.

Rollback khi `appointments.insert` hoac `appointment_services.insert` loi da duoc test bang fault-injected mock trong `customerAppointmentsService.test.js`. De test rollback do tren DB that mot cach deterministic can transaction/RPC test hook hoac disposable fixture co kha nang inject failure. Khong nen pha schema, chen foreign key sai, hoac dung production data de tao loi.

## 12. Rui ro con lai

- Chua co disposable Supabase project trong workspace nen real-DB gate chua duoc chay.
- Service booking hien ket hop nhieu PostgREST request, khong phai mot PostgreSQL transaction/RPC duy nhat. Cleanup o application layer van co the bi gian doan neu process bi kill giua flow.
- Neu can atomicity cho toan bo reserve-slot + create-appointment + link-service, huong ben vung la mot database transaction/RPC co idempotency key; day la thay doi kien truc, khong chi la them test.
