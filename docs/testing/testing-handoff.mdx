# Testing Handoff

Tai lieu nay la ban giao cho nguoi tiep tuc phien kiem thu tu dong cua project Pet Service. Muc tieu la giup tiep tuc dung flow hien tai, khong lam mat ngu canh va khong vo cac test da on dinh.

## 1. Muc tieu cua chuoi kiem thu

Chuoi phase hien tai dang xay mot bo test bai ban cho backend/frontend theo feature quan trong:

- Backend: Jest + Supertest.
- Frontend: Vitest + Testing Library/jsdom.
- Pattern test: AAA, gom `Arrange`, `Act`, `Assert` ro rang.
- Data: dung mock data, Supabase/Prisma/email/storage deu mock o unit/route level.
- Bao cao: moi phase co mot file `.mdx` rieng trong `docs/testing/`.
- Metrics: pass rate, failed/skipped, coverage all-source, coverage theo file/module trong phase.

Nguyen tac quan trong:

- Khong goi database that trong unit/route tests hien tai.
- Khong hardcode secret/token thật.
- Khi them phase moi, them test truoc, chay targeted, sau do chay regression va coverage.
- Sau khi xong phase, cap nhat docs phase, `follow-up-backlog.mdx`, `docs/docs.json`, va `docs/dev/session-log.mdx`.

## 5. Lenh nen chay khi tiep tuc

Targeted backend cho phase dang lam:

```powershell
npm --prefix backend run test:run -- tenFileHoacPattern
```

Targeted frontend cho phase dang lam:

```powershell
npm --prefix frontend run test:run -- tenFileHoacPattern
```

Regression sau khi xong phase:

```powershell
npm --prefix backend run test:run
npm --prefix frontend run test:run
```

Coverage de lay so lieu report:

```powershell
npm --prefix backend run test:coverage
npm --prefix frontend run test:coverage
```

Kiem tra docs/navigation:

```powershell
node -e "JSON.parse(require('fs').readFileSync('docs/docs.json','utf8')); console.log('docs.json ok')"
npm run docs:check
```

Luu y: `npm run docs:check` hien dang fail neu `mint` chua duoc cai hoac chua co trong PATH.

## 6. Phase nen lam tiep

Uu tien hien tai tu backlog:

1. Cap disposable seeded Supabase project va chay `Phase 8B-4 Real DB Appointment Concurrency`.
2. Cap dedicated role accounts va chay `TC-E2E-01` den `TC-E2E-04`.
3. Chot schema/retention neu can luu admin audit log ben vung trong database.
4. Bo sung doctor/staff/customer component coverage con lai.

Neu tiep tuc ngay, nen bat dau bang `Phase 8B-4 Real DB Appointment Concurrency`, vi appointment slot booking la flow co rui ro cao nhat ve duplicate booking. Tuy nhien phase nay co the can database test rieng; neu chua san sang DB test, co the lam `Phase 8E-2` hoac `Phase 8F-2` truoc vi van theo mock/route pattern hien tai.

## 7. Template khi them phase moi

Moi phase moi nen co cac buoc:

1. Doc report phase lien quan va `follow-up-backlog.mdx`.
2. Doc source service/routes lien quan.
3. Them hoac mo rong mock data neu can.
4. Viet test theo AAA.
5. Chay targeted test.
6. Fix loi test hoac production bug neu test phat hien bug that.
7. Chay backend/frontend regression.
8. Chay coverage.
9. Tao file `docs/testing/phase-xx-*.mdx` gom scope, file test, mock data, ket qua, coverage, diem tot, khuyet diem, follow-up.
10. Them file docs vao `docs/docs.json`.
11. Cap nhat `docs/testing/follow-up-backlog.mdx`.
12. Cap nhat `docs/dev/session-log.mdx`.

## 8. Can than khi sua test hien tai

- Khong xoa mock helper cu neu chua kiem tra tat ca suites dung no.
- `backend/tests/helpers/supabaseQuery.js` la helper dung chung; sua o day co the anh huong nhieu phase.
- Route tests thuong mock `authMiddleware` nhung giu real `requireRole` de test authorization boundary.
- Service tests dang mock Supabase theo queue/table; neu test fail bat thuong, kiem tra thu tu `.from()` va thu tu query chain truoc.
- Khong chay command destructive hoac reset git vi worktree dang co nhieu thay doi testing phase chua commit.
