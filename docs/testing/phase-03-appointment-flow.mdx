# Phase 03 Appointment Flow Testing

Phase 3 tap trung vao appointment flow cua customer: lay options, loc danh sach, tim provider, tao lich, xac nhan, doi lich va huy lich. Day la flow co rui ro cao vi lien quan den pet ownership, service/provider compatibility, slot thoi gian va transition trang thai.

## 1. Pham vi

Chuc nang da kiem thu:

- Lay danh sach service co the booking cho customer.
- Loai bo service khong nam trong nhom booking customer.
- Appointment list empty state khi customer chua co pet.
- Provider lookup reject khi thieu customer id.
- Create appointment reject khi thieu pet id.
- Create appointment reject khi pet khong thuoc customer.
- Confirm appointment reject khi appointment khong o trang thai `PENDING`.
- Confirm appointment thanh cong se update status va tao notification cho doctor.
- Cancel appointment reject khi appointment da `COMPLETED`.
- Reschedule appointment reject khi appointment da `COMPLETED`.
- Frontend appointment API goi dung endpoint, method, auth header, body va query string cho options/list/providers/create/confirm/reschedule/cancel.

Ngoai pham vi Phase 3:

- Chua test thanh cong full create appointment do flow nay di qua slot reservation, service insert, email event va reload appointment maps.
- Chua test thanh cong pending reschedule/cancel voi slot rollback.
- Chua test concurrent booking cung slot.
- Chua test customer appointment UI modals bang React Testing Library.
- Chua test route-level `/api/customer/appointments` bang Supertest.

## 3. Quy tac AAA

Tat ca test Phase 3 dung AAA.

Backend status-transition example:

```js
test("rejects confirming appointments that are not pending", async () => {
  // Arrange
  supabase.from
    .mockReturnValueOnce(createSupabaseQuery({ data: completedAppointment, error: null }))
    .mockReturnValueOnce(createSupabaseQuery({ data: appointmentPet, error: null }));

  // Act
  const action = () => confirmCustomerAppointment(`APT-${completedAppointment.id}`, appointmentCustomerId);

  // Assert
  await expect(action()).rejects.toMatchObject({ statusCode: 409 });
});
```

Frontend request-contract example:

```ts
test("reschedules an appointment with requested date and reason", async () => {
  // Arrange
  const input = { date: "2099-07-21", time: "10:00", reason: "Change time" };
  mockFetchJson({ ok: true, appointment: mockAppointment });

  // Act
  await rescheduleCustomerAppointment("APT-000200", input);

  // Assert
  expect(fetch).toHaveBeenCalledWith(
    "http://localhost:5050/api/customer/appointments/APT-000200/reschedule",
    expect.objectContaining({
      method: "PATCH",
      body: JSON.stringify(input),
    }),
  );
});
```

## 7. He thong da lam tot

- Appointment options chi tra ve cac service ma customer duoc booking: MEDICAL, GROOMING va BOARDING.
- Customer appointment list co empty state an toan khi customer chua co pet.
- Appointment creation chan ngay khi thieu pet id hoac pet khong thuoc customer.
- Confirm/cancel/reschedule deu kiem tra status truoc khi thay doi du lieu.
- Confirm appointment tao notification cho doctor khi customer xac nhan lich.
- Frontend appointment API contract ro rang: dung endpoint, method, body, query string va auth header.
- Appointment id duoc encode khi goi action endpoint, giam rui ro loi URL voi id co ky tu dac biet.

## 8. Khuyet diem va rui ro con lai

- Backend `customerAppointmentsService.js` con coverage thap vi file rat lon va gom nhieu flow: slot detection, provider lookup, create success, email, appointment maps, prescriptions, boarding pricing.
- Chua co test cho concurrent booking cung slot, day la rui ro quan trong cua appointment flow.
- Chua co integration test cho create appointment thanh cong voi doctor slot reservation va rollback khi insert appointment/service that bai.
- Chua co route test Supertest cho customer appointment endpoints.
- Chua co component test cho modal dat lich, doi lich, huy lich va detail appointment.
- Chua test service type/provider mismatch thanh cong that bai o duong create sau khi resolve service.
