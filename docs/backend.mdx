## Stack

- Node.js
- Express 5
- Prisma
- PostgreSQL
- Supabase server client
- JWT and bcrypt

## Structure

```text
backend/
  src/
    server.js
    routes/
    services/
    middleware/
    lib/
  prisma/
    schema.prisma
    migrations/
    seed.js
```

## Commands

```powershell
npm --prefix backend run dev
npm --prefix backend run start
npm --prefix backend run prisma:generate
```

## Current Routes

- `/api/health`
- `/api/auth`
- `/api/admin`
  - `GET /api/admin/dashboard` returns admin totals.
  - `GET /api/admin/users` lists customers, doctors, and staff users for the admin user-management page.
  - `GET /api/admin/services` lists service catalog rows for the admin service-management page.
  - `GET /api/admin/appointments` lists appointment rows for the admin appointment page.
  - `GET /api/admin/staff` lists doctor and staff rows for the staff-management page.
  - `GET /api/admin/reports` returns invoice, service, appointment, and staff-performance report data for the admin reports page.
  - `GET /api/admin/settings` returns backend-shaped clinic, account, notification, payment, and security settings data for the admin settings page.
  - `GET /api/admin/exam-context` returns appointment, pet, history, symptom, body-system, and prescription option data for the admin exam page.
  - Existing doctor profile helper routes remain under `/api/admin/doctors`.
- `/api/staff`
  - `GET /api/staff/profile` returns the authenticated staff profile for the staff portal shell.
  - `GET /api/staff/appointments` lists active appointments for staff check-in and service intake.
  - `PUT /api/staff/appointments/:appointmentId/checkin` marks a pending appointment as checked in.
  - `GET /api/staff/grooming` lists grooming work items assigned to the current staff member or unassigned work.
  - `PATCH /api/staff/grooming/:groomingId/status` starts or completes one grooming work item.
  - `GET /api/staff/boarding` lists current boarding guests with today's care status.
  - `PATCH /api/staff/boarding/:boardingId/daily-status` updates today's boarding care checklist for one guest.
  - `GET /api/staff/payments` lists invoice rows for staff payment collection.
  - `PATCH /api/staff/payments/:invoiceId/pay` marks one invoice as paid.
- `/api/doctor`
  - `GET /api/doctor/profile` returns the authenticated doctor's profile.
  - `GET /api/doctor/records` lists appointment-backed patient history for the authenticated doctor, includes pet identity for grouping records by pet, and accepts `search` and `species` filters.
  - `GET /api/doctor/stats` returns doctor statistics for month, week, day, and quarter dashboard views with KPI card view data.
  - `GET /api/doctor/settings` returns doctor profile, schedule, notification, and security/session settings payloads.
  - `GET /api/doctor/exam/:appointmentId` returns exam-screen context for one current-doctor appointment from database rows.
  - `GET /api/doctor/appointments` lists active appointments for the authenticated doctor.
    - The response includes render-ready portal data: appointment rows, status keys, status view classes, schedule summary counts, and header metadata.
  - `PUT /api/doctor/appointments/:appointmentId/start` starts an appointment exam.
  - `PUT /api/doctor/appointments/:appointmentId/complete` completes an appointment exam.
- `/api/customer`
  - `GET /api/customer/pets` lists the current customer's pets.
  - `POST /api/customer/pets` creates a current-customer pet.
  - `PUT /api/customer/pets/:petId` updates a current-customer pet.
  - `GET /api/customer/appointment-options` lists service options for customer booking.
  - `POST /api/customer/appointment-provider-options` lists doctors whose `doctor_schedules` cover the requested slot and are not already booked at that exact date/time, or lists staff for staff-backed services.
  - `GET /api/customer/appointments` lists the current customer's appointments.
  - `POST /api/customer/appointments` creates a pending appointment for a current-customer pet and selected doctor or staff member.
  - `PATCH /api/customer/appointments/:appointmentId/reschedule` updates a customer-owned appointment's schedule.
  - `PATCH /api/customer/appointments/:appointmentId/cancel` cancels a customer-owned appointment.
  - `GET /api/customer/service-history` lists invoice-backed service history for the current customer.
  - `GET /api/customer/invoices/:invoiceId/pdf` exports a customer-owned invoice as a PDF.
  - `GET /api/customer/invoices/latest/pdf` exports the current customer's latest invoice as a PDF.
  - `GET /api/customer/invoices/match/pdf` exports the current customer's invoice matching pet, service, and date query parameters.
  - `GET /api/customer/notifications` lists notifications for the authenticated user.
  - `PATCH /api/customer/notifications/:notificationId/read` marks one authenticated-user notification as read.
  - `PATCH /api/customer/notifications/read-all` marks all authenticated-user notifications as read.

## Rules

- Keep route handlers focused on HTTP concerns.
- Put business logic in `backend/src/services/`.
- Keep database access behind Prisma or existing backend libraries.
- Update API and database docs when contracts change.

Doctor appointment portal schedule shaping lives in `backend/src/services/doctor/doctorAppointmentService.js`; routes should call the service and return its payload.
Doctor records, stats, exam context, and settings shaping lives in `backend/src/services/doctor/doctorService.js`; frontend role pages should render those payloads without rebuilding business-facing rows locally.
Staff portal shaping lives in `backend/src/services/staff/staffPortalService.js`; staff routes should stay thin and return render-ready appointments, grooming tasks, boarding guests, payments, and profile payloads.
Admin dashboard, report, settings, user, service, appointment, and staff-management shaping lives in `backend/src/services/adminService.js`; admin routes should stay thin and return backend-shaped payloads for role pages.
