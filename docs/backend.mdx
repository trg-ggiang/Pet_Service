## Stack

- Node.js
- Express 5
- Prisma
- PostgreSQL
- Supabase server client
- JWT and bcrypt

## Structure

Runtime data access is owned by backend services. Customer appointments use the `/api/customer` route group and the `requested_date` / `requested_time` database fields; the older duplicate appointment API has been removed.

Persisted workflows include password reset under `/api/auth/forgot-password/*`, admin settings under `/api/admin/settings`, and the staff KPI summary under `/api/staff/summary`.

Transactional email workflows use `backend/src/services/emailService.js` and Gmail SMTP. Appointment confirmation, exam result, payment confirmation, and boarding updates send from their corresponding business workflows. Appointment, follow-up, and vaccination reminders run through `npm --prefix backend run email:reminders` or the optional in-process scheduler.

Admin email templates are persisted in `app_settings` and editable from Admin Settings. Supported templates cover password reset, appointment confirmation/reminder, exam results, payment confirmation, follow-up reminders, vaccination reminders, boarding updates, and custom test emails.

```text
backend/
  src/
    server.js
    routes/
    services/
    middleware/
    lib/
  prisma/
    schema.prisma
    migrations/
    seed.js
```

## Current Routes

- `/api/health`
- `/api/auth`
- `/api/admin`
  - `GET /api/admin/dashboard` returns admin totals.
  - `GET /api/admin/users` lists customers, doctors, and staff users with backend search and user-management summary for the admin user-management page.
  - `PATCH /api/admin/users/:role/:id/lock` locks or unlocks one customer, doctor, or staff account from the admin user-management page.
  - `GET /api/admin/services` lists backend-filtered service catalog rows and returns category counts plus service KPI summary for the admin service-management page.
  - `POST /api/admin/services` creates one service catalog row.
  - `PATCH /api/admin/services/:id` updates one service catalog row.
  - `PATCH /api/admin/services/:id/status` activates or deactivates one service catalog row.
  - `GET /api/admin/appointments` lists backend-filtered appointment rows and returns tab counts, service/staff options, and amount summary for the admin appointment page.
  - `PATCH /api/admin/appointments/:id/status` updates one admin appointment status.
  - `GET /api/admin/staff` lists backend-filtered doctor and staff rows with staff-management summary for the staff-management page.
  - `PATCH /api/admin/staff/:id/lock` locks or unlocks one doctor/staff account from the staff-management page.
  - `PUT /api/admin/doctors/:doctorId/schedules` saves a doctor working window and materializes it into concrete 30-minute schedule slots.
  - `GET /api/admin/reports` returns invoice, service, appointment, and staff-performance report data for the admin reports page.
  - `GET /api/admin/settings` returns backend-shaped clinic, account, notification, payment, and security settings data for the admin settings page.
  - `GET /api/admin/exam-context` returns appointment, pet, history, symptom, body-system, and prescription option data for the admin exam page.
  - Existing doctor profile helper routes remain under `/api/admin/doctors`.
- `/api/staff`
  - `GET /api/staff/profile` returns the authenticated staff profile for the staff portal shell.
  - `GET /api/staff/appointments` lists active appointments for staff check-in and service intake.
  - `PUT /api/staff/appointments/:appointmentId/checkin` marks a pending appointment as checked in.
  - `PUT /api/staff/appointments/:appointmentId/complete-grooming` completes an in-progress grooming appointment from the appointment list and creates or updates its unpaid invoice.
  - `GET /api/staff/grooming` lists grooming work items assigned to the current staff member or unassigned work.
  - `PATCH /api/staff/grooming/:groomingId/status` starts or completes one grooming work item. Completing grooming marks the appointment and appointment service complete, then creates or updates an unpaid invoice for the payment tab.
  - `GET /api/staff/boarding` lists current boarding guests with today's care status.
  - `PATCH /api/staff/boarding/:boardingId/daily-status` updates today's boarding care checklist for one guest.
  - `GET /api/staff/payments` lists invoice rows for staff payment collection.
  - `PATCH /api/staff/payments/:invoiceId/pay` marks one invoice as paid.
- `/api/doctor`
  - `GET /api/doctor/profile` returns the authenticated doctor's profile.
  - `GET /api/doctor/records` lists appointment-backed patient history for the authenticated doctor, includes pet identity for grouping records by pet, and accepts `search` and `species` filters.
  - `GET /api/doctor/stats` returns doctor statistics for month, week, day, and quarter dashboard views with KPI card view data.
  - `GET /api/doctor/settings` returns doctor profile, schedule, notification, and security/session settings payloads.
    - Doctor schedules are read-only in the doctor portal; admin owns schedule creation and updates.
  - `GET /api/doctor/exam/:appointmentId` returns exam-screen context for one current-doctor appointment from database rows.
  - `GET /api/doctor/appointments` lists active appointments for the authenticated doctor.
    - The response includes render-ready portal data: appointment rows, status keys, status view classes, schedule summary counts, and header metadata.
  - `PUT /api/doctor/appointments/:appointmentId/start` starts an appointment exam.
  - `PUT /api/doctor/appointments/:appointmentId/exam-complete` saves the exam record, completes the appointment, and creates or updates an unpaid medical-visit invoice for the staff payment tab.
  - `PUT /api/doctor/appointments/:appointmentId/complete` completes an appointment exam and creates or updates an unpaid invoice when a medical visit already exists.
- `/api/customer`
  - `GET /api/customer/pets` lists the current customer's pets.
  - `POST /api/customer/pets` creates a current-customer pet.
  - `PUT /api/customer/pets/:petId` updates a current-customer pet.
  - `GET /api/customer/appointment-options` lists service options for customer booking.
  - `POST /api/customer/appointment-provider-options` lists doctors with an `AVAILABLE` row in `doctor_schedule_slots` for the requested future date/time, or lists staff for staff-backed services. Past slots are rejected server-side.
  - `GET /api/customer/appointments` lists the current customer's appointments with backend filtering, status counts, and pagination summary.
    - Completed appointment rows include prescription items when available.
  - `POST /api/customer/appointments` creates a pending appointment for a current-customer pet and selected doctor or staff member when the requested date/time is in the future.
  - `PATCH /api/customer/appointments/:appointmentId/reschedule` updates or requests a customer-owned appointment schedule change for a future date/time.
  - `PATCH /api/customer/appointments/:appointmentId/cancel` cancels a customer-owned appointment.
  - `GET /api/customer/service-history` lists invoice-backed service history for the current customer with backend type filtering and summary counts.
  - `GET /api/customer/invoices/:invoiceId/pdf` exports a customer-owned invoice as a PDF.
  - `GET /api/customer/invoices/latest/pdf` exports the current customer's latest invoice as a PDF.
  - `GET /api/customer/invoices/match/pdf` exports the current customer's invoice matching pet, service, and date query parameters.
  - `GET /api/customer/notifications` lists notifications for the authenticated user with total and unread summary.
  - `PATCH /api/customer/notifications/:notificationId/read` marks one authenticated-user notification as read.
  - `PATCH /api/customer/notifications/read-all` marks all authenticated-user notifications as read.
  - `DELETE /api/customer/notifications/:notificationId` dismisses one authenticated-user notification.

## Rules

- Keep route handlers focused on HTTP concerns.
- Put business logic in `backend/src/services/`.
- Keep database access behind Prisma or existing backend libraries.
- Update API and database docs when contracts change.

Doctor appointment portal schedule shaping lives in `backend/src/services/doctor/doctorAppointmentService.js`; routes should call the service and return its payload.
Doctor records, stats, exam context, and settings shaping lives in `backend/src/services/doctor/doctorService.js`; frontend role pages should render those payloads without rebuilding business-facing rows locally.
Staff portal shaping lives in `backend/src/services/staff/staffPortalService.js`; staff routes should stay thin and return render-ready appointments, grooming tasks, boarding guests, payments, and profile payloads.
Admin dashboard, report, settings, user, service, appointment, and staff-management shaping lives in `backend/src/services/adminService.js`; admin routes should stay thin and return backend-shaped payloads for role pages. Admin staff management accepts `department`, `status`, and `search` query parameters and returns `staff` plus `summary` so the frontend does not rebuild filters or KPI counts locally.
